# 03 · 数据库与业务逻辑说明

> 本文说明 `info.gwt` 配置文件、SQLite 数据结构、水电费计算公式、
> 月度账期引擎、提醒逻辑与三端通知适配方案。

---

## 一、本地配置文件 `info.gwt`

### 1.1 为什么需要它

水费单价、电费单价、提醒提前天数属于**全局固定参数**，用文本文件保存：
- 一眼可见、可手工修改；
- 换手机/备份时能一起带走；
- 完全离线，不依赖任何云端。

### 1.2 文件位置

| 场景 | 路径 |
|---|---|
| 项目源码模板 | 项目根目录 `info.gwt`、`assets/info.gwt` |
| APP 运行时 | 应用私有目录 `files/info.gwt`（首次启动自动从 assets 释放） |

### 1.3 字段说明

```ini
# 计费参数
water_price=6            # 水费单价（元/吨），默认 6
elec_price=1.2           # 电费单价（元/度），默认 1.2

# 通知提醒
remind_days=7            # 未缴费提醒提前天数
expire_remind_days=30    # 租期到期提醒提前天数
notify_enabled=1         # 是否开启系统通知（1/0）
focus_enabled=1          # 是否开启澎湃OS 焦点通知（1/0）

# 运行期数据（APP 自动维护）
notice_read_ids=         # 内置通知中心已读消息 ID
```

### 1.4 读写流程

```
APP 启动
  └─ AppConfig.init()
       ├─ 首次：rootBundle 读 assets/info.gwt → 写入 files/info.gwt
       └─ 读取 files/info.gwt → 解析到内存字段

设置页修改
  └─ AppConfig.update(...)
       └─ 立即写回 files/info.gwt → notifyListeners() → UI 刷新
```

代码位置：`lib/core/config/app_config.dart`

## 二、SQLite 数据库设计

数据库文件：`rental.db`（应用私有数据库目录）
代码位置：`lib/data/db/database_helper.dart`

### 2.1 `rooms` 房间信息表

| 字段 | 类型 | 说明 |
|---|---|---|
| `room_no` | TEXT PK | 房间号 |
| `rent` | INTEGER | 租金（元/月） |
| `paid` | INTEGER | 实付（本月已收房租） |
| `room_type` | TEXT | 房型 |
| `tenant` | TEXT | 承租人 |
| `id_card` | TEXT | 身份证 |
| `check_in` | TEXT | 入住日期 yyyy-MM-dd |
| `expire` | TEXT | 到期日期 yyyy-MM-dd |
| `elec_prev` | INTEGER | 上期电表（度） |
| `elec_curr` | INTEGER | 本期电表（度） |
| `water_prev` | INTEGER | 上期水表（吨） |
| `water_curr` | INTEGER | 本期水表（吨） |
| `water_fee` | INTEGER | 水费（元） |
| `elec_fee` | INTEGER | 电费（元） |
| `utility_fee` | INTEGER | 水电费合计（元） |
| `utility_paid` | INTEGER | 水电收缴（1=已收 / 0=未收） |
| `card_count` | INTEGER | **小豆豆** —— 一楼大门磁卡数量（张） |
| `key_count` | INTEGER | 钥匙（把） |
| `deposit` | INTEGER | 押金（元） |
| `ac` | INTEGER | 空调（台） |
| `heater` | INTEGER | 热水器（台） |
| `fridge` | INTEGER | 冰箱（台） |
| `washer` | INTEGER | 洗衣机（台） |

### 2.2 `people` 租户信息表

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增主键（实现增删改查所需） |
| `room_no` | TEXT | 房间号（外键 → rooms，级联删除） |
| `name` | TEXT | 姓名 |
| `phone` | TEXT | 电话 |

### 2.3 `payments` 缴费流水表

> **为什么多一张表**：`rooms` 只能存「当期快照」，历史账单会被下月覆盖。
> `payments` 按「房间 + 费用类型 + 账期」归集，支撑缴费统计 / 历史账单 / 欠费累计。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增主键 |
| `room_no` | TEXT | 房间号 |
| `pay_type` | TEXT | `rent`（房租）/ `utility`（水电费） |
| `period` | TEXT | 账期 `yyyy-MM` |
| `due` | INTEGER | 应收（元） |
| `paid` | INTEGER | 实收（元） |
| `is_settled` | INTEGER | 是否结清 |
| `pay_time` | TEXT | 实际缴费时间 |
| `remark` | TEXT | 备注 |

唯一约束：`UNIQUE(room_no, pay_type, period)`

## 三、水电费计算公式

代码位置：`lib/core/utils/calc_util.dart`

```
用电量   = max(0, 本期电表 − 上期电表)          单位：度
用水量   = max(0, 本期水表 − 上期水表)          单位：吨
电费     = 用电量 × elec_price                  单位：元
水费     = 用水量 × water_price                 单位：元
水电费合计 = 电费 + 水费
```

- 金额计算保留两位小数，落库时四舍五入到「元」（整数字段）；
- 若录入的本期读数 < 上期读数，界面会红字提示「读数异常」，
  并按 0 计算用量，保存前二次确认，防止误录倒转导致账单出错；
- 单价修改后立即生效（写入 `info.gwt`），下一次抄表按新单价计算。

## 四、月度账期引擎（自动结转）

代码位置：`lib/data/repository/payment_repository.dart`

**触发时机**：APP 启动时（`main.dart`）。

```
对每一个房间：
  1. 查找该房间最近一条 utility 流水的账期 lastPeriod
  2. 若 lastPeriod < 当前账期（说明跨月了）：
       a. 把上一账期的 utility 流水补齐为最终金额（due = rooms.utility_fee）
       b. 把上一账期的 rent 流水补齐为最终实收（paid = rooms.paid）
       c. rooms 表滚动：
            elec_prev  = elec_curr     # 本期读数变上期
            water_prev = water_curr
            elec_fee / water_fee / utility_fee / utility_paid 全部清零
            paid = 0                   # 新一期房租重新应收
  3. 若当前账期还没有流水，则自动创建：
       rent    : due = rooms.rent,  paid = rooms.paid
       utility : due = 0（尚未抄表）, paid = 0
```

**效果**：每月第一次打开 APP，抄表页自动归零、上期读数自动结转，
历史账单完整保留在 `payments` 里，可在「缴费统计」按月查看。

## 五、提醒逻辑

代码位置：`lib/services/reminder_engine.dart`

### 5.1 三类提醒

| 类型 | 触发条件 | 级别 |
|---|---|---|
| **房租未缴** | 房间已入住、`rent > 0`、当前账期未结清，且今天在「每月 1 日 ~ remind_days 日」提醒窗口内 | 临近窗口末尾升级为 danger |
| **租期到期** | `expire` 距今 ≤ `expire_remind_days` 天 | ≤3 天或已过期为 danger |
| **水电未收** | `utility_fee > 0` 且 `utility_paid = 0` | warn |

### 5.2 内置通知中心

- 每次进首页 / 通知中心页都会重算一次；
- 消息 ID 规则：`类型-房间号-账期`，已读状态写入 `info.gwt` 的 `notice_read_ids`；
- 列表按「紧急优先、房间号排序」。

## 六、三端通知适配

代码位置：
- Dart：`lib/services/notification_service.dart`
- 原生：`android/.../notify/NotificationHelper.kt`、`FocusNotificationHelper.kt`
- 后台：`android/.../service/ReminderForegroundService.kt`

### 6.1 通知渠道

| 渠道 ID | 名称 | 优先级 |
|---|---|---|
| `general_notice` | 通用提醒 | DEFAULT |
| `rent_remind` | 房租与租期提醒 | HIGH |
| `utility_remind` | 水电费提醒 | HIGH |
| `focus_notice` | 焦点通知 | HIGH |

### 6.2 通用 Android 系统通知

- Android 13+ 自动申请 `POST_NOTIFICATIONS` 运行时权限；
- 使用 `BigTextStyle` 展开显示全部未缴房间；
- 每类提醒只发一条汇总通知，避免刷屏。

### 6.3 后台常驻提醒

- `ReminderForegroundService` 前台服务常驻，显示一条不可滑动的运行状态通知；
- 每 **30 分钟** 通过 MethodChannel 唤醒 Dart 层重算一次提醒；
- `START_STICKY` 让服务被系统杀死后自动重启；
- 可在「设置中心」一键开关。

### 6.4 小米澎湃OS / HyperOS 焦点通知

**⚠️ 重要说明（普通开发者权限，无需企业认证）**

1. 焦点通知是小米在系统通知之上的「状态栏胶囊 / 灵动岛」增强协议，
   通过往通知 extras 写入 `miui.focus.ticker` / `miui.focus.title` /
   `miui.focus.icon_id` / `miui.focus.param` 来声明焦点内容。
2. **严格意义上的「模板化焦点通知」需要在小米开放平台提交焦点模板**，
   个人开发者也可以申请，无需企业认证；审核通过后把
   `FocusNotificationHelper.kt` 中的 `template` 改成你的模板 ID 即可。
3. **未申请模板时**：本 APP 会把字段写入，系统可能忽略；
   此时自动**降级为高优先级常驻通知**，提醒功能 100% 受影响。
4. 该设计原则是 **能用就用、不能用就安全降级**，任何异常都不影响普通通知。

**申请路径（可选）**：小米开放平台 → 焦点通知 → 提交模板 → 通过后替换模板 ID。

### 6.5 通知开关

`info.gwt` 中 `notify_enabled` / `focus_enabled` 控制；
在「设置中心」修改后立即生效并写回文件。

## 七、数据备份与恢复

- **备份**：`rental.db` + `info.gwt` → 打成 `zufang_guanjia_backup_yyyyMMdd_HHmmss.zip`
  → 通过系统分享发送（微信 / 网盘 / 本地文件均可）；
- **恢复**：系统文件选择器（SAF）选取 zip → 解压覆盖数据库与配置 → 自动重载；
- **全程离线**，不经过任何云端。

代码位置：`lib/services/backup_service.dart`、`android/.../MainActivity.kt`
