# 飞书多维表格同步

在「设置 → 飞书多维表格」填写自己的 App Token、Table ID、App ID 和 App Secret。
公开源码及 APK 不预置个人连接参数。应用为飞书企业自建应用，以 tenant_access_token 调用接口，
需要为应用开放多维表格记录读写、字段读取/创建权限，并为目标表格授予应用访问权限。

## 使用方式

1. 首次使用点「立即同步 / 首次上传」。APP 先生成本机备份，再上传现有数据。
2. 新设备如需使用已有云端数据，点「从飞书初始化缓存」，确认覆盖本地；执行前自动备份。
3. 启用自动同步后，前台每 30 秒检查，本地数据广播或配置变化后延迟 3 秒同步。
   Android 后台不保证执行，断网时继续使用本地缓存。
4. 同一条数据在双方均有不同修改时停止同步。请先备份并核对，不自动以最后写入覆盖。

## 表结构

现有数据表添加两个多行文本字段，原有字段和无同步键的记录不删除：

- `rental_key`：`rental-v1/rooms/房号`、`people/id`、`payments/id`、`receipts/id`、`config/配置键`。
- `rental_json`：完整行 JSON 或配置值 JSON 字符串。中文使用 UTF-8。

数据按行存储，而非把 SQLite 二进制文件塞进单元格；可修改 JSON 的非主键值。
不要删除必需配置、修改主键、创建重复键，或在一次修改尚未同步完成时由其他设备并发写入。
客户端会检查重复键、字段、房间引用及同步冲突，但飞书记录接口不提供跨所有行的原子事务，
不能将此设计视为多设备同时收款的强一致数据库。网络中断后的部分上传会保留旧基线重试。

本地 `rental.db` 和 `info.gwt` 是离线缓存；同步基线是设备私有文件，不随备份分享。
租户、账单、收据、计费和 API 配置均上传到目标表格。

## 密钥与备份

直连方案的 App Secret 保存于实机私有 info.gwt，token 仅在内存缓存并提前刷新。
备份包及云端配置行含飞书和大模型密钥，**不是加密保险箱**。请限制表格协作者，勿公开分享备份。
聊天中暴露的密钥建议轮换；不要将连接值提交仓库或打包进默认 assets。
